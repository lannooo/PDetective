# PDetective
A novel framework for Detecting Partial Deepfake Speech

## Quick Start 
This section provides a minimal workflow to reproduce the Best results of PDetective reported in the paper. 
#### Step 1: Environment Setup
Please follow the instructions in **Environment Setup** to create the conda environment and install dependencies. 
#### Step 2: Dataset Preparation
Download the required datasets and organize them following the structure described in **Dataset → Data Directory**. 
If your local dataset paths differ, update the corresponding dataset configuration files under `config/assess/` as described in **Dataset → Data Directory**. 
#### Step 3: Training
Train the PDetective model using: 
```bash
bash scripts/PDetective.sh train
```
#### Step 4: Evaluation
Evaluate the trained checkpoint. Before evaluation, make sure to update the checkpoint path in the bash script:
```bash
bash scripts/PDetective.sh eval
```

## Environment Setup
- Python: >= 3.9
- CUDA: 12.6

Install conda environment as follows:
```
conda create -n pdetect python=3.9
conda activate pdetect
pip install -r requirements.txt
```

## Dataset Preparation
### PES Dataset
The PES dataset used in our experiments has been anonymously released on the Zenodo platform. Link: [PES Database](https://doi.org/10.5281/zenodo.18206266)

### Other Public Dataset
- [PartialSpoof](https://zenodo.org/records/5766198)
- [LlamaPartialSpoof](https://zenodo.org/records/14214149)

### Data Directory
Make sure that the dataset directory has a structure like:
```
data/
  ├── PES/
  │     ├── annotations/
  │     ├── dev/
  │     ├── train/
  │     ├── eval/
  │     └── ...
  ├── PartialSpoof/
  │     ├── database/ 
  │     └── ... 
  ├── LLamaPartialSpoof/
  │     ├── R01TTS.0.b/ 
  │     └── ...
  └── ...
```
**Note**: If your local dataset is not organized following the directory structure shown above, you can still run all experiments by modifying the dataset configuration files under <code>config/assess/</code>.
Simply update the <code>data_root</code> field in the corresponding config file so that it points to the actual location of your dataset. <br>
Example:
```
datasets:
  eval_set:
    - name: llama-b
      label_root: ...
      data_root: /path/to/LlamaPartialSpoof/R01TTS.0.b
      dur_lst: ...
```
### Labels
The frame-level labels are scored in files like <code>xxx_0.02.npy</code> file. The dataset provides frame-level labels at a fine temporal resolution of **0.02 seconds per frame**.
During training and evaluation, our code automatically aggregates these fine-grained labels into coarser segments as required by the model or experiment configuration. No manual processing is needed from the user.

For the LlamaPartialSpoof dataset, frame-level labels can be generated by running:
```
python prepare_llamaps.py
```
Both PartialSpoof and PES datasets already include frame-level label files, so no additional processing is required from the user.


## Training and Evaluation
Both training and evaluation are performed using the same script located under <code>scripts/{model}.sh</code>.
For example, to train the PDetective model, run:
```
bash scripts/PDetective.sh train
```
To evaluate a trained checkpoint on other datasets, run:
```
bash scripts/PDetective.sh eval
```
**Note**: Before running evaluation, make sure to update the checkpoint path inside the corresponding bash script so that it points to the correct trained model. <br>
In the training/eval bash script, modify the field of <code>ASSESS_CONFIG</code> and <code>EVAL_ASSESS_CONFIG</code> to switch training and evaluation datasets.

## Configurations
#### Model Configs
YAML files in <code>config/model/</code> define the architecture and hyperparameters of model (including the self-supervised feature frontend, fine-tuning mode, optimizer & scheduler, loss definitions).

#### Dataset Configs
YAML files in <code>config/assess/</code> define the data loading hyperparameters and the dataset configs for train/dev/eval
- <code>1_PES_cap_base_xxx.yaml</code>: Baseline training without data augmentation.
- <code>1_PES_cap_aug_xxx.yaml</code>: PES training with various augmentation strategies enabled.

- <code>0_eval_PES_xxx.yaml</code>: Defines multiple evaluation subsets, including subsets for each forgery type (PES-eval-Ful, PES-eval-CaP, PES-eval-Edi), the full PES-eval set, and the unseen condition with previously unseen synthesis models (PES-unseen).
- <code>0_eval_xxx_xxx.yaml</code>: Defines other public datasets.


## Reproducibility
Experiments are conducted with fixed random seeds specified in the configuration files. Minor numerical differences may occur due to differences in hardware, CUDA versions, or library implementations.

All results reported in the paper can be reproduced by training the models from scratch using the provided scripts and configurations.
