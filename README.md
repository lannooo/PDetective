# 🕵️‍♂️ PDetective

This is the official implementation for our ACM MM'26 paper "**PDetective: Beyond Shallow Artifacts in Partial Deepfake Speech Detection**"

**Abstract**: With the rapid advancement of fine-grained speech synthesis, partial deepfake speech has emerged as an increasingly concerning threat.
Recent end-to-end speech editing systems further exacerbate this challenge by enabling acoustically and perceptually seamless partial forgeries, leading to the systematic failure of existing partial deepfake detectors. Our investigation of existing partial deepfake detection models reveals that these models exhibit a critical learning bias toward model-specific shallow decoding artifacts, which fundamentally undermines their generalization. To address this issue, we propose PDetective, a framework that mitigates artifact-dependent decision-making through targeted training constraints, encouraging the model to learn more intrinsic and stable representations. We further introduce a large-scale partial editing spoofing dataset comprising more than 250k utterances to underpin and validate our framework. Experiments demonstrate that PDetective significantly improves cross-domain generalization, reducing EER by over 11\% on unseen editing-based forgeries, and achieving an average EER reduction of over 30\% relative to the best-performing baselines in cross-dataset evaluations.

## 🔍 Overview

**PDetective** is a novel framework designed for **partial deepfake speech detection**, supporting fine-grained detection and excellent generalization across diverse forgery paradigms and unseen synthesis models.

## 🚀 Quick Start

This section outlines the minimal workflow to reproduce the **best-performing results** reported in the paper.

### Step 1: Environment Setup

Create the conda environment and install dependencies following the instructions in [Environment Setup](#Environment-setup)

### Step 2: Dataset Preparation

Download the required datasets and organize them according to the structure described in [Dataset Preparation](#dataset-preparation).
If your local dataset paths differ, update the corresponding dataset configuration files under `config/assess/`.

### Step 3: Training

Train the PDetective model using:

```bash
bash scripts/PDetective.sh train
```

### Step 4: Evaluation

Before evaluation, update the checkpoint path inside the bash script, then run:

```bash
bash scripts/PDetective.sh eval
```

## 🛠 Environment Setup

- Python: >= 3.9
- CUDA: 12.6

Install conda environment as follows:

```
conda create -n pdetect python=3.9
conda activate pdetect
pip install -r requirements.txt
```

## 📂 Dataset Preparation

The **PES dataset** used in our experiments has been anonymously released on the Zenodo platform. Link: [PES Database](https://doi.org/10.5281/zenodo.18206266)

Other Public Dataset available at:

- [PartialSpoof](https://zenodo.org/records/5766198)
- [LlamaPartialSpoof](https://zenodo.org/records/14214149)
- [HAD](https://zenodo.org/records/10377492)
- [PartialEdit](https://zenodo.org/records/15519188)

Organize all datasets under a common data/ directory::

```
data/
  ├── PES/
  │     ├── annotations/
  │     ├── dev/
  │     ├── train/
  │     ├── eval/
  │     └── ...
  ├── PartialSpoof/
  │     ├── database/ 
  │     └── ... 
  ├── LLamaPartialSpoof/
  │     ├── R01TTS.0.b/ 
  │     └── ...
  └── ...
```

**Note**: If your local dataset is not organized following the directory structure shown above, you can still run all experiments by modifying the dataset configuration files under `config/assess/[...]`. Simply update the `data_root` field in the corresponding config file so that it points to the actual location of your dataset. Example:

```
datasets:
  eval_set:
    - name: llama-b
      label_root: ...
      data_root: /path/to/LlamaPartialSpoof/R01TTS.0.b
```

The frame-level labels are scored in files like `xxx_0.02.npy` file. The dataset provides frame-level labels at a fine temporal resolution of **0.02 seconds per frame**.
During training and evaluation, our code automatically aggregates these fine-grained labels into coarser segments as required by the model or experiment configuration.

Both PartialSpoof and PES datasets already include frame-level label files, so no additional processing is required.
For the LlamaPartialSpoof / HAD / PartialEdit dataset, frame-level labels can be generated by running:

```
python prepare_llamaps.py
python prepare_partialedit.py
python prepare_had.py
```

## 🧪 Training & Evaluation

Both training and evaluation are performed using the same script located under `scripts/{model}.sh`.
For example, to train the PDetective model, run:

```
bash scripts/PDetective.sh train
```

To evaluate a trained checkpoint on other datasets, run:

```
bash scripts/PDetective.sh eval
```

**Note**: Before running evaluation, make sure to update the checkpoint path inside the corresponding bash script so that it points to the correct trained model.
In the training/eval bash script, modify the field of `ASSESS_CONFIG` and `EVAL_ASSESS_CONFIG` to switch training and evaluation datasets.

## ⚙️ Configuration Files

#### Project Config

`config.toml` file defines the paths used in the project, including cache, experiment result, etc. Modify it as needed.

#### Model Config

YAML files in `config/model/` defines the architecture and hyperparameters of model (including the self-supervised feature frontend, fine-tuning mode, optimizer & scheduler, loss definitions).

#### Dataset Config

YAML files in `config/assess/` define the data loading hyperparameters and the dataset configs for train/dev/eval

- `1_PES_cap_base_xxx.yaml`: Baseline training without data augmentation.
- `1_PES_cap_aug_xxx.yaml`: PES training with various augmentation strategies enabled.
- `0_eval_PES_xxx.yaml`: Defines multiple evaluation subsets, including subsets for each forgery type (PES-eval-Ful, PES-eval-CaP, PES-eval-Edi), the full PES-eval set, and the unseen condition with previously unseen synthesis models (PES-unseen).
- `0_eval_xxx_xxx.yaml`: Defines other public datasets.

## 🔁 Reproducibility

Experiments are conducted with fixed random seeds specified in the configuration files. Minor numerical differences may occur due to differences in hardware, CUDA versions, or library implementations.
